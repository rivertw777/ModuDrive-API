# 파일/폴더 공유 기능 스펙

이 문서는 "공유" 기능이 어떤 규칙으로 동작하는지 정의한 문서입니다. 개발 지식이 없어도
읽을 수 있도록, 코드 용어 대신 실제 화면에서 벌어지는 상황을 기준으로 설명합니다.

---

## 1. 소유자 및 공유 권한

- **소유자**: 파일/폴더를 만든 사람. 공유 설정을 걸고, 바꾸고, 없애는 것은 **오직 소유자만**
  할 수 있습니다.
- **공유 권한**: 권한에 따라 세부 동작을 허용합니다.

  | 권한 | 할 수 있는 것 |
  |---|---|
  | 뷰어 | 보기, 다운로드 |
  | 편집자 | 보기, 다운로드, 이름 변경 |

---

## 2. 직접 공유와 상속 공유

공유는 두 가지 경로로 생깁니다.

- **직접 공유**: 소유자가 특정 사람(이메일)을 지정해서 이 파일/폴더 하나에 권한을 부여하는 것.
- **상속 공유**: 폴더를 공유하면, 그 폴더 안의 모든 하위 파일·폴더가 별도 설정 없이도
  자동으로 같은 권한을 물려받는 것. 하위 항목 하나하나에
  권한이 복사되어 저장되는 게 아니라, 접근할 때마다 "이 파일 위에 공유된 폴더가 있는지"를
  즉시 계산합니다. 즉 상위 폴더의 공유를 바꾸면 하위 전체에 실시간으로 반영됩니다.

### 2.1. 세부 규칙

- **폴더를 공유하면** → 그 폴더의 모든 하위 파일/폴더가 몇 단계 아래에 있든 동일한 권한을
  자동으로 갖습니다. 손자 폴더, 그 안의 파일까지 예외 없이 적용됩니다.
- **직접 공유와 상속 공유가 동시에 있으면** → **직접 공유가 항상 이깁니다.** 상위 폴더에서
  물려받은 권한이 더 높더라도, 이 파일에 소유자가 따로 지정해 둔 권한이 있으면 그 권한만
  적용됩니다.
  - 예시 상황:
    ```
    상위 폴더        (상속 권한: 편집자)
    └ 파일.txt       (직접 공유: 뷰어)   → 최종 권한: 뷰어

    상위 폴더        (상속 권한: 뷰어)
    └ 파일.txt       (직접 공유: 편집자) → 최종 권한: 편집자
    ```
  - 결과: 
    두 경우 모두 파일 자신에게 걸린 직접 공유가 상위 폴더의 상속 권한을 그대로 덮어씁니다.
- **직접 공유가 없고 상속만 있는 경우** → 여러 상위 폴더에서 각각 공유되어 있을 수 있는데
  (예: 조부모 폴더와 부모 폴더가 같은 사람에게 서로 다른 권한을 준 경우), 이때는
  **가장 가까운 상위 폴더의 권한**이 적용됩니다.
  - 예시 상황:
    ```
    조부모 폴더      (A씨: 편집자)
    └ 부모 폴더      (A씨: 뷰어)
      └ 파일.txt     (A씨에게 직접 공유 없음) → 최종 권한: 뷰어
    ```
  - 결과:
    부모 폴더가 더 가까우므로 A씨는 파일에서 **뷰어**입니다 (조부모의 "편집자"가 더 높은
    권한이어도 적용되지 않습니다).
- **폴더 목록 화면(공유받은 폴더 안을 둘러볼 때)** → 폴더 자체에 걸린 권한과 그 위 조상
  폴더들의 권한 중 **가장 가까운 것**을 "이 폴더를 통해 물려받는 권한"으로 보여주고, 그
  폴더 안의 각 파일은 위 규칙과 동일하게 "그 파일 자신의 직접 공유가 있으면 그것을 우선,
  없으면 물려받는 권한"으로 표시됩니다.
- **가입하지 않은 이메일로 공유하면** → 정식 계정이 없으므로 "초대장" 상태로 보관되고,
  나중에 그 이메일로 가입하는 순간 자동으로 정식 공유로 연결됩니다. 그동안에도 메일로 받은
  링크로는 접근할 수 있지만, 3번에서 설명하듯 로그인 전에는 보기·다운로드만 되는 화면이라
  편집자로 초대받았어도 편집은 못 하고, 실제 초대받은 역할은 가입해서 로그인한 뒤부터
  적용됩니다.
- **자기 자신에게 공유하거나, 이미 공유된 사람을 다시 공유하려 하면** → 거부됩니다
  (소유자는 애초에 공유 대상이 될 필요가 없고, 중복 공유는 의미가 없기 때문).
- 소유자 자신에게는 공유 행(row)이 따로 만들어지지 않습니다.

## 3. 액세스 범위 지정

"누구에게 공유할지"를 두 가지 범위 중 하나로 정합니다.

| 범위 | 의미                                                     |
|---|----------------------------------------------------------|
| 권한이 부여된 사용자 (기본값) | 소유자와, 소유자가 이메일로 직접 초대한 사람만 접근 가능 |
| 링크가 있는 모든 사용자 | 링크(URL)를 가진 사람은 **누구나** 접근 가능             |

### 3.1. 세부 규칙

- **"링크가 있는 모든 사용자"는 항상 "뷰어" 권한을 가집니다.** 링크는 소지한 모든 사람이 접근할 수 있으므로 기본적으로
  "편집" 권한을 부여하지 않습니다. 편집 권한이 필요하면 반드시 2번의 "직접 공유"로 이메일을 지정해야 합니다.
- 링크를 눌렀을 때 실제로 어떤 화면이 보이는지, 세부 동작은 4번("링크 제공")에서
  다룹니다.
- **폴더를 "권한이 부여된 사용자"로 전환하면("링크가 있는 모든 사용자"를 끄면)** → 그 폴더 자체뿐 아니라, 그 폴더 하위에서
  **개별적으로** "링크가 있는 모든 사용자"로 켜 둔 파일/폴더까지 전부 함께 꺼집니다. "상위 폴더만 잠그고
  하위의 개별 링크는 살아있는" 상태가 되지 않도록, 하위 트리 전체를 훑어서 정리합니다.
- **조상 폴더 중 하나라도 "링크가 있는 모든 사용자" 상태인데, 그 안의 파일 하나만 "권한이 부여된 사용자"로 바꾸려 하면**
  → "상위 폴더의 액세스 권한을 삭제하시겠습니까?" 경고 모달이 뜨고, **"링크가 있는 모든 사용자"로 되어 있는 조상 폴더 
  전부(그 밑의 모든 파일·폴더 포함)의 액세스 범위가 함께 "권한이 부여된 사용자"로 바뀝니다.** 조상이 한 단계가 아니라 여러
  단계여도 마찬가지로, 그중 "링크가 있는 모든 사용자"인 조상은 전부 대상입니다.
  - 예시 상황:
    ```
    조부모 폴더 G    (링크가 있는 모든 사용자)
    └ 부모 폴더 P    (링크가 있는 모든 사용자)
      └ 파일 F       (권한이 부여된 사용자로 변경 시도) → 경고 모달 → 확인 시 G, P, F 모두 "권한이 부여된 사용자"
    ```
  - 결과: 
    조상 폴더를 포함한 하위의 파일들의 액세스 범위가 "권한이 부여된 사용자"로 변경됩니다.

## 4. 링크 제공

파일/폴더의 접근 링크(주소)를 실제로 눌렀을 때 무엇이 보이는지는, 그 파일의 액세스 범위(3번)와
누른 사람이 로그인했는지·실제 권한을 갖고 있는지의 조합으로 정해집니다.

| 액세스 범위 | 방문자 | 결과                         |
|---|---|------------------------------|
| 권한이 부여된 사용자 | 비로그인 | 로그인 페이지로 이동         |
| 권한이 부여된 사용자 | 로그인 + 권한 없음 | 접근 거부                    |
| 권한이 부여된 사용자 | 로그인 + 직접/상속 공유 있음 | 평소 쓰는 화면으로 바로 진입 |
| 링크가 있는 모든 사용자 | 비로그인 | 그대로 보여줌(뷰어 화면)     |

### 4.1. 세부 규칙

- **로그인한 사람이 링크와 상관없이 이미 그 파일에 대한 실제 접근 권한**(소유자, 또는
  직접/상속 공유)을 갖고 있다면, 보기·다운로드만 되는 링크 전용 화면이 아니라 평소 쓰는
  전체 화면으로 바로 연결됩니다.
- **"링크가 있는 모든 사용자" 상태에서 처음 보는 비로그인 방문자**는 보기·다운로드만 되는 별도 화면을 보게 됩니다.
- **미가입 초대 링크**는 이 표의 "링크가 있는 모든 사용자"와는 다른, 그 사람 한 명 전용 캡슐(`?key=` 토큰)로
  동작합니다. 가입 후 로그인하면 위 표의 "직접/상속 공유 있음" 경로로 자연히 흡수되어 토큰 자체가 더는 필요 없어집니다.

## 5. 공유 권한 수정

공유해 둔 사람의 권한(뷰어 ↔ 편집자)을 바꾸는 기능입니다.

### 5.1. 세부 규칙

- **소유자만** 수정할 수 있습니다.
- **상속 공유(상위 폴더에서 물려받아 보이는 항목)의 역할을 이 화면에서 고르면, 기존
  상속 원본을 고치는 게 아니라 이 파일에 대한 새 직접 공유가 만들어집니다. 이에 따라 
  직접 공유가 상속 원본을 즉시 덮어씁니다. 상위 폴더의 원본 공유 자체는 지워지지 않고
  그대로 남아 있습니다(다른 하위 항목에는 계속 그대로 적용됨).

---

## 6. 공유 권한 삭제

공유해 둔 사람의 권한을 삭제하는 기능입니다.

### 6.1. 세부 규칙

- **소유자만** 삭제(해제)할 수 있습니다.
- 삭제 시 동작은 3번의 액세스 범위 변경과 동일한 패턴입니다 — **이 사람에게 조상 폴더의 공유가 남아 있으면**
  경고 모달을 띄우고, 확인 시 **이 사람의** 조상 공유들만 함께 삭제됩니다. 조상 폴더 하위에 다른 파일에 대한 직접 공유가
  존재한다면, 그건 각자 독립된 행이라 영향받지 않습니다. 
  - 예시 상황:
    ```
    조부모 폴더 G    (A씨: 편집자)
    └ 부모 폴더 P    (A씨: 뷰어)
      └ 파일 F       (A씨: 편집자, 직접 공유)

    F에서 A씨 삭제 시도 → 경고 모달 → 확인 시 F, P, G의 A씨 공유 모두 삭제
    ```
  - 결과: 조상 폴더를 포함한 하위의 파일들의 공유가 제거됩니다. (직접 공유 제외)
